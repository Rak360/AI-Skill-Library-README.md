# Android-First Weekly Marketing Workflow

**Designed for:** Android 13+, low-memory device, under 5 GB free storage.  
**Goal:** Keep production moving without installing large apps or filling the phone.

## Daily workflow

### 1. Brief and facts — 5 minutes
- Open the campaign brief and identify objective, audience, placement, offer, CTA, deadline, and approved facts.
- For medical/aesthetic content, confirm treatment facts and route clinical claims for qualified review.
- Do not paste patient information, lead exports, passwords, or tokens into public AI tools.

### 2. Draft — 10 minutes
- Use `skills/video-script-writer.md` for video scripts.
- Use `skills/performance-ad-creative-strategist.md` for ad angles and tests.
- Use `templates/image-prompt-templates.md` for visual prompts.
- Generate one useful first draft, then refine it; avoid generating many large image/video variants on the phone.

### 3. Produce — 10–20 minutes
- Prefer browser-based tools already available.
- Keep source assets in an approved cloud folder and download only the file needed now.
- Use a single editor rather than installing multiple overlapping apps.
- Start with short 720p samples when storage is low; only increase output size after a successful test.

### 4. Quality check — 5 minutes
- Spelling and readability on a small phone screen.
- Correct logo, colors, aspect ratio, CTA, destination, and tracking link.
- No fabricated facts, outcomes, testimonials, guarantees, or unauthorized images.
- Check subtitles, sound, and exported file from start to finish.
- Obtain the required human/clinical approval before publishing.

### 5. Record — 2 minutes
Update the content tracker with status, owner, source links, approvals, publish date, and results. Do not store sensitive patient or lead data in the public GitHub repository.

## Storage policy

- Check free storage before every video export.
- Keep at least 5–8 GB free where possible; if under 2 GB, do not install new creative apps or export large projects.
- Delete only files you recognize and have backed up where needed.
- Clear app cache only when appropriate; avoid Clear data/Storage as a first step.
- Upload and verify the original in approved storage before removing the local copy.

## Weekly review — 15 minutes

- Which asset took the most time?
- Which repetitive step can be simplified?
- Which creative result is supported by actual performance data?
- Is a new tool genuinely needed, or can the existing workflow solve it?
- Before adopting a tool, check license, maintenance, permissions, data handling, and cost.
- Update the GitHub resource catalog only for meaningful changes; do not add resources solely to make the list longer.
